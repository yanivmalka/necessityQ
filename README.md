# necessityQ — אפליקציית רשימת קניות לומדת (Android)

רשימת קניות משותפת לבני הבית. האפליקציה לומדת מה הבית קונה, באיזו כמות ובאיזה קצב, ומציעה בהקשה אחת את מה שכנראה עומד להיגמר.

הפריטים נשמרים לפי **כינוי המוצר ולא לפי היצרן**: "קוטג' תנובה 5%" ו-"קוטג 5%" הם אותו פריט, ו-"קוטג' 9%" הוא פריט אחר.

## מה יש בגרסה הראשונה

- **הוספה מהירה בטקסט חופשי:** `2 קוטג' 5%`, `חצי קילו גבינה צהובה`, `1.5 ק"ג עגבניות`, `חלב 3% 2 ליטר`, `שתי חבילות פסטה`.
- **נרמול שמות:** הסרת שמות חברות, איחוד כתיבים (קוטג/קוטג'/קוטג׳, עגבניה → עגבניות), ושמירת המאפיין המבחין (אחוזי שומן, ללא לקטוז) כחלק מזהות הפריט.
- **איחוד כמויות:** הוספה של פריט שכבר ברשימה מוסיפה לכמות שלו (500 גרם + 1 ק"ג = 1.5 ק"ג) במקום לשכפל אותו.
- **"כנראה נגמר בקרוב":** הצעות לפי קצב הקנייה, עם הסבר ("בדרך כלל כל 5 ימים · נקנה לפני 4 ימים"). דחייה של הצעה משתיקה אותה לחצי מהמחזור.
- **"קונים בדרך כלל":** כפתורי הוספה מהירה לפריטים הנפוצים, מדורגים לפי תדירות שמשקלה דועך עם הזמן.
- **השלמה אוטומטית:** קודם מההיסטוריה של הבית, ואחר כך מקטלוג של כ-100 פריטים כלליים.
- **עבודה משותפת בזמן אמת:** כל שינוי מופיע מיד אצל כל בני הבית. יש עבודה מלאה אופליין, והשינויים מסתנכרנים כשהחיבור חוזר.
- **מסך היסטוריה:** קצב, כמות טיפוסית, מועד צפוי, ומחיקה של רישום קנייה שגוי.
- **ממשק עברי מימין לשמאל**, Material 3, ותמיכה בערכת נושא כהה.

## איך הסטטיסטיקה עובדת

החישוב שקוף ובלי למידת מכונה: כל ההחלטות אפשר להסביר, ויש להן בדיקות.

1. **רישום:** כל סימון "נקנה" נרשם כקנייה. מזהה הקנייה נגזר מהשורה, כך שאם שני בני בית מסמנים יחד נרשמת קנייה אחת.
2. **קיבוץ לפי יום:** קניות של אותו פריט באותו יום נחשבות לקנייה אחת.
3. **נרמול מרווחים:** כל מרווח בין קניות מחולק בגודל הקנייה היחסי (בטווח 0.5–3). כך קנייה כפולה לא נראית כמו קצב איטי.
4. **קצב:** חציון משוקלל של המרווחים, שבו לקניות אחרונות יש משקל גבוה יותר (דעיכה 0.8). החישוב מתבסס על 12 הקניות האחרונות בלבד.
5. **מועד צפוי:** הקנייה האחרונה ועוד הקצב, כפול גודל הקנייה האחרונה ביחס לכמות הטיפוסית.
6. **ביטחון:** עולה עם מספר המרווחים ויורד ככל שהפיזור (MAD) גדל. פריט "קבוע" הוא פריט עם 4 קניות לפחות ופיזור נמוך.
7. **הצעה:** פריט מוצע כשעבר 80% מהמחזור שלו. הניקוד הוא הביטחון כפול היחס בין הזמן שעבר למחזור, עד 2.

## ארכיטקטורה

```
domain/   Kotlin טהור, בלי Android ובלי Firebase: כל כללי העסק, ובדיקות JUnit
  ItemIdentity, Catalog, HebrewText   זהות פריט כללי ונרמול עברית
  QuickEntryParser, Quantity          פענוח כמויות ויחידות
  ConsumptionStatsEngine              קצב, כמות טיפוסית, מועד צפוי
  SuggestionEngine, ListRules         הצעות, השתקה, איחוד שורות
  ShoppingService                     תרחישי השימוש (מעל ממשקי Repository)
  Ports                               HouseholdRepository, ShoppingRepository
app/      Android (Jetpack Compose)
  data/firebase                       Firestore בזמן אמת, אופליין, עדכונים ברמת שדה
  data/local                          מצב מכשיר יחיד (קובץ JSON) כשאין Firebase
  ui/                                 ViewModel יחיד שמעליו המסכים
```

- **מקור אמת אחד:** ה-UI מאזין לזרמים בזמן אמת (`Flow`) מה-Repository, ו-`ShoppingService.snapshot()` מחשב מחדש רשימה, סטטיסטיקה והצעות בכל שינוי של כל אחד מבני הבית.
- **עבודה במקביל:** כל עריכה מעדכנת רק את השדות שהשתנו (last-writer-wins ברמת שדה). סימון "נקנה" והחזרה לרשימה הם פעולות אטומיות (batch).
- **ממשקים בגבולות:** הדומיין לא מכיר את Firebase, כך שאפשר להחליף backend (למשל לשרת ‎.NET מתוכנית התכנון) בלי לגעת בכללים.
- **אבטחה:** [`firebase/firestore.rules`](firebase/firestore.rules). רק חברי הבית קוראים וכותבים, ומשתמש יכול להוסיף או להסיר רק את עצמו.

## בנייה והפצה אוטומטית

כל דחיפה ל-`main` מפעילה את [`.github/workflows/android.yml`](.github/workflows/android.yml), שמבצע:

1. בדיקות יחידה לדומיין.
2. Lint ובניית APK חתום.
3. פרסום **GitHub Release** עם קובץ ה-APK. בטלפון: Releases ← הקובץ העדכני ← התקנה.
4. פריסת כללי Firestore, אם הוגדרו הסודות המתאימים.

### הגדרות (Settings → Secrets → Actions)

| סוד | חובה? | תפקיד |
| --- | --- | --- |
| `GOOGLE_SERVICES_JSON` | לסנכרון בין בני הבית | תוכן הקובץ `google-services.json` מ-Firebase (חבילה: `app.necessityq`). בלעדיו האפליקציה נבנית במצב מכשיר יחיד. |
| `FIREBASE_PROJECT_ID`, `FIREBASE_SERVICE_ACCOUNT` | לפריסת כללים | מזהה הפרויקט ו-JSON של Service Account עם הרשאת Firebase Rules Admin. |
| `KEYSTORE_BASE64`, `SIGNING_STORE_PASSWORD`, `SIGNING_KEY_ALIAS`, `SIGNING_KEY_PASSWORD` | מומלץ | מפתח חתימה קבוע לגרסאות אמיתיות. בלעדיו משמש `keystore/dev.keystore` (מפתח פיתוח בלבד). |

### הקמת Firebase (פעם אחת)

1. ב-console.firebase.google.com: יוצרים פרויקט ומוסיפים אפליקציית Android עם החבילה `app.necessityq`.
2. Authentication → Sign-in method → מפעילים **Anonymous**.
3. Firestore Database → Create database.
4. מורידים את `google-services.json` ושומרים את תוכנו בסוד `GOOGLE_SERVICES_JSON`.
5. מפרסמים את הכללים מ-`firebase/firestore.rules`, ידנית או דרך הסודות לפריסה.

## מחירים מקבצי השקיפות (סניפים ומחירים)

הנתונים מגיעים מהקבצים שרשתות המזון מחויבות לפרסם לפי חוק המזון (שקיפות מחירים). שירות קליטה רץ ב-Cloud Functions באזור **`me-west1` (תל אביב)**, כי חלק מאתרי הרשתות חוסמים גישה מחו"ל. הקוד נמצא ב-[`firebase/functions`](firebase/functions).

**מה השירות עושה:**

1. **רשימת סניפים:** קורא את קובצי ה-Stores של הרשתות המוגדרות, משאיר רק סניפים בערים שבהיקף (ברירת מחדל: ירושלים), וממיר כתובות לקואורדינטות דרך OpenStreetMap Nominatim, עם מטמון. התוצאה נשמרת ב-`prices/branchIndex`.
2. **מחירים לסניפים שנבחרו:** לכל סניף שבית כלשהו בחר (`households/{hid}/settings/priceBranches`), השירות טוען את קובץ ה-PriceFull העדכני. הוא שומר תמונת מצב דחוסה ב-Storage (`prices/{branchId}.json.gz`) עם היסטוריית שינויים וטווח מחירים (מינימום ומקסימום לאורך חלון זמן). הסטטוס נשמר ב-`priceBranches/{branchId}`.
3. **תזמון:** הפונקציה `pricesTick` רצה כל שעה, אבל טוענת סניף רק כשעבר `refreshHours` מהטעינה הקודמת. ברירת המחדל היא 24, כלומר פעם ביום. בנוסף, כשנכנסים למצב "בקנייה", האפליקציה מבקשת רענון לסניפים שעודכנו לפני יותר מ-12 שעות (הפונקציה `refreshBranch`).

**פלטפורמות נתמכות:** שופרסל, Cerberus/PublishedPrices (רמי לוי, אושר עד, יוחננוף, טיב טעם, סופר יודה, קשת טעמים ועוד), PublishPrice (קרפור/יינות ביתן) ו-Laibcatalog (ויקטורי, מחסני השוק).

**הגדרות מנהל:** מסמך `config/prices` ב-Firestore, שעורכים בקונסולה. כל השדות אופציונליים:

| שדה | ברירת מחדל | משמעות |
| --- | --- | --- |
| `refreshHours` | `24` | תדירות רענון המחירים לכל סניף (רזולוציית העדכון) |
| `storesRefreshDays` | `7` | תדירות קריאה מחדש של רשימות הסניפים |
| `rangeDays` | `90` | חלון טווח המחירים שמוצג למשתמש |
| `cities` | `["ירושלים"]` | הערים שבהיקף הנתונים |
| `chains` | שופרסל, רמי לוי, אושר עד, יוחננוף, ויקטורי, קרפור, סופר יודה, טיב טעם | מפתחות רשתות מתוך `chains.ts` |
| `manualRefreshMinutes` | `60` | בקשת רענון מהאפליקציה נדחית אם הנתונים צעירים מזה |
| `admins` | `[]` | מזהי UID שמורשים להפעיל את `refreshBranchList` |

**הפעלה (פעם אחת):**

1. לעבור לתוכנית **Blaze** בפרויקט Firebase, ולהפעיל את **Storage**.
2. לחשבון השירות שבסוד `FIREBASE_SERVICE_ACCOUNT` צריכות להיות ההרשאות Cloud Functions Admin, Service Account User, Cloud Scheduler Admin ו-Firebase Rules Admin, או התפקיד Editor.
3. ב-GitHub, תחת Settings ← Secrets and variables ← Actions ← Variables, להגדיר משתנה `PRICES_DEPLOY` עם הערך `true`. מאותו רגע כל דחיפה ל-`main` שנוגעת ב-`firebase/` פורסת את הפונקציות ואת כללי ה-Storage, דרך [`.github/workflows/functions.yml`](.github/workflows/functions.yml).

**הגנת תקציב (ניתוק חיוב אוטומטי):** הפונקציה `budgetGuard` מאזינה לנושא ה-Pub/Sub `billing-budget`. כשהעלות החודשית מגיעה לתקציב, היא מנתקת את חשבון החיוב מהפרויקט. מאותו רגע השירותים בתשלום נעצרים, והפרויקט חוזר למכסות החינמיות. מחברים את החיוב מחדש ידנית בקונסולה. ההגדרות נמצאות במסמך `config/billing`: השדה `enabled` (ברירת מחדל `true`) מפעיל או מכבה את המנגנון, והשדה `cutAtRatio` (ברירת מחדל `1`, כלומר 100%) קובע באיזה אחוז מהתקציב לנתק. כדי שזה יעבוד צריך שני דברים:
1. בתקציב, תחת Billing ← Budgets & alerts, לחבר את הנושא `billing-budget` ("Connect a Pub/Sub topic to this budget").
2. לתת לחשבון השירות של הפונקציה (`<project-number>-compute@developer.gserviceaccount.com`) את התפקיד **Project Billing Manager**.

בדיקות: `cd firebase/functions && npm ci && npm run check`.

## פיתוח מקומי

Android Studio (Narwhal ומעלה) עם JDK 17.

- `./gradlew :domain:test`: בדיקות הלוגיקה.
- `./gradlew :app:installDebug`: התקנה על מכשיר.
